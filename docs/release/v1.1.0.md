# cache-mod v1.1.0

A fix release with one security-relevant correction to `SizedCache`, a
faster `TtlCache`, and borrowed-key lookups. No breaking changes. MSRV
stays at Rust 1.75.

## Security: `SizedCache` could return another key's value

In 1.0.0 and earlier, an update that made a value larger than the
remaining budget evicted other entries but left their keys in the index.
A later `get` of an evicted key then panicked, or, once the freed slot had
been reused by another insert, returned that other key's value. `remove`
of the stale key could unlink the wrong entry and spread the damage.

Any `SizedCache` whose values change size on update was affected. In a
cache keyed per user or per session, one user could receive another
user's data. Upgrade is recommended for every user of `SizedCache`.

All eviction paths now share one routine that removes the index entry
together with the slot. A property test drives the cache with values that
grow and shrink on update and checks every result against a model.

## `TtlCache` eviction no longer scans the shard

Each shard now keeps a deadline index next to its map. Finding the
soonest-expiring entry on overflow reads the front of the index instead
of scanning every entry under the lock.

| Capacity | Insert at capacity, 1.0.0 | 1.1.0 |
|---|---|---|
| 16 000 | 2.0 us | 0.45 us |
| 160 000 | 14.8 us | 0.45 us |

`len` dropped from 15 to 270 us to about 230 ns at the same sizes. Every
operation is O(log n) in the shard size.

## Borrowed-key lookups

Every cache type has `get_by`, `contains_key_by` and `remove_by`. They
take any borrowed form of the key, so a `String`-keyed cache can be
queried with a `&str` without allocating:

```rust
use cache_mod::{Cache, LruCache};

let cache: LruCache<String, u32> = LruCache::new(64).expect("capacity > 0");
cache.insert("requests".to_string(), 1);
assert_eq!(cache.get_by("requests"), Some(1));
```

The `Cache` trait is unchanged.

## Other fixes

- A panic in a key's `Hash` or `Eq` during eviction no longer leaves the
  index pointing at a freed slot.
- Constructors reserve at most 1024 slots per shard up front, so huge
  capacities such as `usize::MAX` no longer panic and a large configured
  capacity no longer commits its memory at start-up.
- `LfuCache::get` no longer clones the key on every hit.

## Documentation

- `SizedCache` bounds only what the weigher reports. Keys, per-entry
  overhead and zero-weight values are outside the budget; the docs now
  say so and show a weigher with a fixed per-entry charge for untrusted
  input.
- `docs/STABILITY.md` no longer describes `SizedCache` as sharded.
